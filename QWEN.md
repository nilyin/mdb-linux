# MedvedDB Project Context

## Project Overview

MedvedDB is a NoSQL distributed database written in C, designed for high availability and eventual consistency. Key features include:

* **Fully Decentralized**: No single points of failure.
* **ACID Compliance**: Transactional properties via LMDB storage.
* **Data Integrity**: Verified serialization and type safety.
* **CRUD Operations**: Create, Read, Update, Delete operations verified with the server.
* **Multi-language Bindings**: Available for C, Java, Python, and C# via SWIG.

The system is composed of several core components:
* `mdv_platform`: Core utilities (memory, data structures, concurrency, networking).
* `mdv_storage`: LMDB-based persistence layer.
* `mdv_crypto`: Cryptographic functions for data integrity.
* `mdv_net`: Networking components for P2P communication.
* `mdv_types`: Type system for serialization and data validation.
* `mdv_core`: Core distributed database logic (consensus, replication).
* `mdv_service`: The main server daemon.
* `mdv_api`: Public C API.
* `mdv_client`: C client library.
* `mdv_bindings`: Language bindings generated by SWIG.
* `mdv_tests`: Comprehensive test suite for all components.

## Building and Running

### Prerequisites

* Docker (recommended for consistent builds and testing)
* CMake (for native builds)
* GCC/Clang (for native builds)

### Building

#### Docker Build (Recommended)

A persistent Docker volume is used for build caching to significantly speed up incremental builds.

```bash
# Create persistent build cache
docker volume create mdv_build_cache

# Fast build and data consistency verification (Recommended)
./scripts/test_data_consistency.sh

# Incremental build
./scripts/incremental_build.sh

# Manual build with cache
docker run --rm -v "$(pwd)":/app -v mdv_build_cache:/app/build -w /app medveddb-test:latest bash -c "cd build && cmake .. && make -j4"
```

#### Native Build

```bash
mkdir build
cd build
cmake ..
cmake --build .
```

### Running

#### Running the Server

The server requires a configuration file.

```bash
# Using the built binary
./build/mdv_service/medved --cfg=assets/conf/medved.conf

# Using Docker
docker run --rm -p 4800:4800 -v "$(pwd)":/app -v mdv_build_cache:/app/build -w /app medveddb-test:latest bash -c "cd build && ./mdv_service/medved --cfg=../assets/conf/medved.conf"
```

#### Running Tests

Various test scripts are provided for different levels of verification.

```bash
# Fast core components test
./scripts/test_data_consistency.sh

# Core components + server verification
./scripts/run_core_tests.sh

# Complete test suite (Recommended)
./scripts/run_complete_tests.sh

# Comprehensive execution (CI/CD)
./scripts/run_all_tests_final.sh

# Native tests
./build/mdv_tests/mdv_tests
```

### Testing Language Bindings

#### Java Bindings

To test the Java bindings with CRUD operations:

1. **Build the project** to generate SWIG Java bindings and native library:
   ```bash
   cd /app && mkdir -p build && cd build && cmake .. && make mdv4j -j4
   ```

2. **Navigate to the Java bindings directory**:
   ```bash
   cd /app/build/mdv_bindings/mdv/java
   ```

3. **Add package declaration** to the Java test file:
   ```bash
   sed -i '1i package mdv;' CrudTest.java
   ```

4. **Compile the test file** using the generated JAR:
   ```bash
   javac -cp "mdv4j.jar:.\" CrudTest.java
   ```

5. **Start the MedvedDB server**:
   ```bash
   cd /app/build && ./mdv_service/medved --cfg=../assets/conf/medved.conf &
   ```

6. **Create proper package directory structure** and move the test class file:
   ```bash
   cd /app/build/mdv_bindings/mdv/java
   mkdir -p mdv && mv CrudTest.class mdv/
   ```

7. **Run the test** with correct classpath and library path:
   ```bash
   java -cp ".:mdv4j.jar" -Djava.library.path="." mdv.CrudTest
   ```

To stop the server after testing:
```bash
pkill -f medved
```

## Development Conventions

* **Language**: Primarily C11.
* **Build System**: CMake.
* **Testing**: MinUnit framework for C tests. Extensive test suite covering platform, types, storage, crypto, and CRUD operations.
* **Containerization**: Docker is used extensively for testing and development environments, providing a consistent setup and build caching.
* **Documentation**: Doxygen is used for generating documentation from source code comments.
* **Continuous Integration**: GitHub Actions are used for CI (see `.github/workflows`).
